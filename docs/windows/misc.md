## 看上去 windows 提供的 api 只有 c++ 接口，rust 如何解决
尝试在 windows 上使用 rust 看看

差不多是这个意思了，这个结果是在 Linux 上执行 codex 的结果:

也就是，通过 bindings.txt 提供从 c++ 到 rust 的转换
```txt
当前本机 Rust 1.94.0 的 std 里，Windows 平台依赖声明是 windows-targets，不是 windows-sys：

/home/martins3/.rustup/toolchains/stable-x86_64-unknown-linux-gnu/lib/rustlib/src/rust/library/std/Cargo.toml:58

但 std 内部确实有一个生成出来的 windows_sys.rs。
Windows 平台层里：

/home/martins3/.rustup/toolchains/stable-x86_64-unknown-linux-gnu/lib/rustlib/src/rust/library/std/src/sys/pal/windows/c.rs:11

mod windows_sys;
pub use windows_sys::*;

这个文件说明是自动生成的：

/home/martins3/.rustup/toolchains/stable-x86_64-unknown-linux-gnu/lib/rustlib/src/rust/library/std/src/sys/pal/windows/c/
README.md:1

The `windows_sys.rs` file is autogenerated from `bindings.txt`

所以准确说：

Rust std on Windows
不是通过你的项目依赖 windows-sys crate
而是 std 自己带了一份内部生成的 Windows API 绑定
并用 windows-targets 提供链接宏/目标库支持

例如内部绑定会声明 CreateFileW、CreateProcessW、WSAStartup、NtCreateFile 这类 Windows API，然后 std::fs、std::process、std::net 等
再基于这些实现。
```
