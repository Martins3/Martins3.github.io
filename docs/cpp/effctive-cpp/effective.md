# 《Effective C++》规则速览

> Scott Meyers 的《Effective C++（第三版）》副标题是“改善程序与设计的 55 个具体做法”，下面按原书顺序列出全部 55 条。

## 一、让自己习惯 C++

1. 把 C++ 看作由 C、面向对象 C++、模板 C++ 和 STL 组成的语言联邦。
2. 尽量用 `const`、`enum` 和 `inline` 替代 `#define`。
3. 尽可能使用 `const`。
4. 确保对象在使用前已经初始化。

## 二、构造、析构与赋值

5. 了解编译器会自动生成和调用哪些特殊成员函数。
6. 明确禁止使用不需要的编译器生成函数；现代 C++ 使用 `= delete`。
7. 多态基类应声明虚析构函数。
8. 不要让异常逃出析构函数。 // FIXME
9. 不要在构造函数或析构函数中调用虚函数。
10. 赋值运算符应返回 `*this` 的引用。 // FIXME
11. 在 `operator=` 中正确处理自赋值。
12. 复制对象时不要遗漏任何成员或基类部分。

## 三、资源管理

13. 使用对象管理资源，即采用 RAII。
14. 仔细设计资源管理类的复制行为。
15. 资源管理类应在必要时提供对原始资源的访问。
16. `new` 和 `delete` 的形式必须匹配，数组应使用 `new[]` 和 `delete[]`。
17. 将 `new` 出来的对象立即放入智能指针，并使用独立语句完成。

## 四、设计与声明

18. 让接口容易被正确使用，而且不容易被误用。
19. 把类的设计当作类型的设计。
20. 传递对象时优先使用 `const` 引用，而不是按值传递。
21. 必须返回新对象时，不要试图返回引用。
22. 将数据成员声明为 `private`。
23. 能用非成员、非友元函数实现时，优先于成员函数。
24. 若所有参数都需要隐式类型转换，应将相关函数声明为非成员函数。
25. 考虑提供不抛异常的 `swap`。 // FIXME

## 五、实现

26. 尽可能推迟变量定义，直到真正需要它时。
27. 尽量少做类型转换。
28. 避免返回指向对象内部数据的句柄，如引用、指针或迭代器。
29. 努力编写异常安全的代码。
30. 理解 `inline` 的适用场景和代价。
31. 尽量减少文件之间的编译依赖。

## 六、继承与面向对象设计

32. 公有继承必须表达 “is-a” 关系。 // FIXME
33. 避免遮蔽继承而来的名称。
34. 区分接口继承与实现继承。
35. 考虑虚函数以外的设计方案。
36. 不要重新定义继承而来的非虚函数。
37. 不要重新定义继承而来的函数默认参数值。
38. 用组合表达 “has-a” 或 “根据某物实现” 的关系。// FIXME
39. 谨慎使用私有继承。 // FIXME
40. 谨慎使用多重继承。

## 七、模板与泛型编程

41. 理解隐式接口和编译期多态。
42. 理解 `typename` 的两种含义。
43. 了解如何访问模板化基类中的名称。
44. 将与模板参数无关的代码移出模板，避免代码膨胀。
45. 使用成员函数模板接受所有兼容类型。
46. 需要隐式类型转换时，在类模板内部定义非成员函数。
47. 使用 traits 类表达和查询类型信息。
48. 了解模板元编程。

## 八、定制 `new` 与 `delete`

49. 理解 `new-handler` 的行为。
50. 理解何时值得替换 `new` 和 `delete`。
51. 编写自定义 `new` 和 `delete` 时遵循惯例。
52. 编写 placement `new` 时，也要编写对应的 placement `delete`。

## 九、其他

53. 重视编译器警告。
54. 熟悉标准库；书中提到的 TR1 已被后续 C++ 标准大体吸收。
55. 熟悉 Boost，但现代 C++ 中应先检查标准库是否已有对应设施。
