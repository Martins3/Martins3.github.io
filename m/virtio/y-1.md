## dummy_complete_rq 是否在软中断

并不是总是在软中断执行，具体看 blk_mq_complete_request_remote

当 hw queue 只有一个的时候:

1. 发现 taskset -ac 1 之后，taskset 才可以集中 cpu 的消耗，否则三个 cpu 分到其他的 cpu 上，恰好绕开接受中断的 CPU

当 hw queue 两个时候:

1. 自动集中的
1. 全部硬中断，发生的 CPU 和接受的 cpu 也是正好错开

1. 为什么会总是错开?
1. hw queue=1 的时候，为什么分散开?

## 为什么虚拟机中显示的 device id 和 qemu 中设置的不同

这里的 device id 无论设置什么，最后都是会显示为:
```txt
00:0d.0 Unclassified device [00ff]: Red Hat, Inc. Device [1af4:106a] (rev 01)
```

在 hw/virtio/virtio-pci.c::virtio_pci_device_plugged 中，会去修正 virtio 设备的 pci
```c
        pci_set_word(config + PCI_VENDOR_ID,
                     PCI_VENDOR_ID_REDHAT_QUMRANET);
        pci_set_word(config + PCI_DEVICE_ID,
                     PCI_DEVICE_ID_VIRTIO_10_BASE + virtio_bus_get_vdev_id(bus));
        pci_config_set_revision(config, 1);
```

这个是预期的，但是为什么会有这个问题，暂时不知道。
