# 共享 GPU 内存深度分析

## 问题

`gpu_shared_vram.exe` 只增加了 83 MiB，而不是预期的 512 MB。

## 根本原因

### Windows "共享 GPU 内存"的真正含义

```
┌─────────────────────────────────────────────────────────────┐
│                    GPU 内存架构                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌───────────────────────┐    ┌──────────────────────────┐ │
│  │   专用 GPU 显存        │    │    系统内存              │ │
│  │   (Dedicated VRAM)    │    │    (System RAM)          │ │
│  │                       │    │                          │ │
│  │  • 物理显存芯片       │    │  • 普通内存条            │ │
│  │  • 速度快             │    │  • 速度慢                │ │
│  │  • 容量有限           │    │  • 容量大                │ │
│  └───────────┬───────────┘    └───────────┬──────────────┘ │
│              │                            │                │
│              │ 溢出 (当专用显存满时)       │                │
│              └────────────────────────────┘                │
│                            │                                │
│                    ┌───────┴───────┐                        │
│                    │ 共享 GPU 内存  │                        │
│                    │ (Shared GPU)  │                        │
│                    │               │                        │
│                    │ 系统内存中 GPU│                        │
│                    │ 可访问的部分  │                        │
│                    └───────────────┘                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**关键发现**:

Windows 任务管理器中的"共享 GPU 内存"指的是：
> **当专用显存不足时，驱动自动溢出到系统内存的部分**

它**不是**简单的 STAGING 缓冲区或系统内存分配！

## 测试结果

### 测试 1: STAGING 缓冲区（专用显存未满）

```
分配: 512 MB STAGING 缓冲区
专用显存: 无变化
共享内存: +2.88 MB (几乎无变化)
```

### 测试 2: 专用显存分配（触发溢出）

```
分配: 7168 MB 专用显存 (超过 RTX 4060 的 8GB 限制)

专用显存: 2422 MB → 7086 MB (+4664 MB)
共享内存:  424 MB → 2987 MB (+2562 MB)  ← 溢出到系统内存！
```

**结论**: 共享内存只在专用显存满时才会增加！

## D3D11 缓冲区类型分析

| 类型 | 位置 | 计入"共享内存"? | 用途 |
|-----|------|---------------|------|
| DEFAULT | 专用显存 | ❌ (算专用) | GPU 独占资源 |
| STAGING | 系统内存 | ❌ | CPU↔GPU 传输 |
| DYNAMIC | 系统内存 | ❌ | 频繁 CPU 更新 |
| IMMUTABLE | 专用显存 | ❌ (算专用) | 只读资源 |

**所有 CPU 可访问的缓冲区都在系统内存，但都不直接计入"共享 GPU 内存"！**

## 如何真正增加"共享 GPU 内存"

### 方法 1: 填满专用显存（推荐）

```c
// 分配大量专用显存，迫使驱动溢出到共享内存
gpu_dedicated_vram.exe 7168  // 分配 7GB
```

### 方法 2: 创建大量渲染目标

当专用显存满了，新的纹理/缓冲区会自动使用共享内存。

### 方法 3: 使用大量视频内存

同时运行多个占用显存的程序（游戏、3D 应用等）。

## 监控方法

### Windows 性能计数器

```powershell
# 共享内存
Get-Counter "\GPU Adapter Memory(*)\Shared Usage"

# 专用内存
Get-Counter "\GPU Adapter Memory(*)\Dedicated Usage"

# 总提交内存
Get-Counter "\GPU Adapter Memory(*)\Total Committed"
```

### nvidia-smi

```bash
# 注意：nvidia-smi 只显示专用显存使用情况
nvidia-smi --query-gpu=memory.used,memory.total

# 对于共享内存，使用 Windows 计数器
```

## 程序更新

### 原程序: gpu_shared_vram.exe

使用 STAGING 缓冲区。在系统内存中，但不计入"共享 GPU 内存"。

### 新程序: gpu_shared_vram_v2.exe

同样使用 STAGING 缓冲区，增加了 Map/Unmap 操作。仍然不计入共享内存。

### 建议

如果要看到"共享 GPU 内存"增加：

```powershell
# 先填满专用显存
gpu_dedicated_vram.exe 6144 10

# 然后分配额外的内存，会溢出到共享内存
gpu_dedicated_vram.exe 2048 10
```

## 结论

| 问题 | 答案 |
|-----|------|
| 为什么只增加 83 MB? | STAGING 缓冲区在系统内存，但不计入"共享 GPU 内存" |
| 什么是"共享 GPU 内存"? | 专用显存溢出到系统内存的部分 |
| 如何触发共享内存增加? | 填满专用显存，迫使驱动使用系统内存 |
| 如何监控? | 使用 Windows 性能计数器，不是 nvidia-smi |
