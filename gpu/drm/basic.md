# 一、整体数据流总览（先记这条主线）
**Framebuffer(显存像素) → Plane → CRTC → Encoder → Connector → 物理屏幕**
数据就是严格按这个顺序一路往后送。

# 二、逐个详解 + 通俗比喻 + 内核定义 + 作用 + 区别
## 1. Plane 图层 / 平面
### 是什么
DRM 里的**图层**，就是**单独的一张画面**。
你可以理解成 **PS、视频剪辑里的图层**。

### 详细作用
1. 只负责：**从显存 framebuffer 读取像素数据**
2. 做基础处理：缩放、裁剪、格式转换（RGB/YUV）、位置偏移、透明度混合
3. **不产生时序、不合成多图层、不输出信号**

### 分类（内核固定三种）
- **Primary Plane 主平面**：必须有，屏幕底层背景画面
- **Overlay Plane 叠加平面**：上层图片、视频画面、UI
- **Cursor Plane 光标平面**：鼠标箭头图层，硬件光标

### 特点
- 一个 **Plane 只能绑定一个 CRTC**
- 一个 **CRTC 可以挂多个 Plane**（多个图层叠在一起）
- 现代显卡都支持多平面叠加，实现视频窗口、桌面、鼠标分层渲染，不用CPU合成。

### 比喻
**一张张透明画纸**，每一张画纸就是一个 Plane。

---

## 2. CRTC 显示控制器（你之前打错的 CTRT）
### 是什么
整个 DRM 流水线**最核心的大脑**，全称 Cathode Ray Tube Controller，名字老旧但概念沿用。

### 详细作用
1. **图层合成**：把多个 Plane（所有画纸）从上到下叠起来，混合成**一整幅完整画面**
2. **生成显示时序**：HSync、VSync、行场同步信号、分辨率、刷新率、像素时钟
3. 处理 VBlank 垂直空白、页面翻转 page flip、gamma 伽马校正
4. 管理整个输出的全局状态

**CRTC 不负责把画面变成 HDMI/DP 信号，只管合成+出标准像素流+时序**。

### 绑定关系
多个 Plane → 汇聚到 **一个 CRTC**

### 比喻
**画板 + 灯光时序控制器**
把所有透明画纸叠好铺平，并且规定**每隔多久刷新一整幅画面**。

---

## 3. Encoder 编码器
### 是什么
CRTC 输出的是**标准内部像素流+时序**，Encoder 负责**格式转换**。

### 详细作用
把 CRTC 合成好的完整画面，转换成对应接口的**电气信号格式**
比如：
- 并行 RGB 信号
- LVDS
- eDP
- HDMI
- DP

它只做**信号编码转换**，不管理图层、不管理时序生成，只做翻译。

### 绑定关系
**一个 CRTC 可以连多个 Encoder，但同一时刻只能用一个**
（多路输出切换用）

### 比喻
**信号翻译官**
画板上完整的画，翻译成屏幕能看懂的专属信号语言。

---

## 4. Connector 连接器
### 是什么
**物理接口抽象**，对应你板子/电脑上真实的接口。
HDMI口、DP口、Type-C显示口、eDP屏幕、LVDS屏幕，每一个物理口对应一个 Connector。

### 详细作用
1. 描述物理接口信息：接口类型、热插拔检测 HPD、屏幕分辨率能力
2. 读取显示器 EDID（屏幕参数、支持分辨率）
3. 最终把 Encoder 转好的信号，**直接输出到外接屏幕**

### 绑定关系
**一个 Encoder 对应一个或多个 Connector**
一般是一一对应。

### 比喻
**插线孔 + 接口外壳**
所有信号最终从这个孔输出到真实屏幕。

---

# 三、超精简一句话总结（背这个就够）
1. **Plane**：**图层**，单张画面，来自显存帧缓冲
2. **CRTC**：**合成+时序**，把所有图层叠成完整一帧，控制刷新率
3. **Encoder**：**编码转换**，把内部画面转成接口信号格式
4. **Connector**：**物理接口**，最终输出到屏幕

# 四、完整整条流水线流程图（必看）
```
显存 Framebuffer
        ↓
   多个 Plane（图层：桌面、视频、鼠标）
        ↓  叠加合成
        CRTC （生成时序、刷新率、整帧画面）
        ↓  信号格式转换
        Encoder
        ↓
        Connector（物理接口：HDMI/eDP/DP）
        ↓
        真实显示屏
```

# 五、最容易混淆的高频疑问（90%人都搞混）
## 1. CRTC 和 Encoder 到底差在哪？
- **CRTC 管画面内容、帧率、图层**
- **Encoder 只管信号格式**
举例子：
同一块合成好的画面，**同一个CRTC**，可以通过不同 Encoder 分别走 HDMI 输出、eDP 输出。

## 2. 为什么要分这么多层？不能合并吗？
硬件本身就是这么设计的：
GPU内部硬件模块本来就分层：
**图层单元 → 合成单元 → 信号编码单元 → 物理接口**
DRM 只是把硬件模块**软件抽象一一对应**。

## 3. 数量关系（面试必考）
- 多个 Plane → 1 个 CRTC
- 1 个 CRTC → 多个 Encoder（分时复用）
- 1 个 Encoder → 多个 Connector
- 1 个 Connector 最终对应 **一块独立屏幕**

## 4. 多屏显示原理
系统里有**多个 CRTC**，每个 CRTC 独立一套合成、独立时序，就能**同时驱动多个完全独立的屏幕**。

# 六、生活化终极比喻（最好记）
把**显示一整个屏幕画面**，比作**看电视**：
1. **Plane**：电视里的多个画面窗口（主画面、小弹窗、字幕、鼠标）
2. **CRTC**：电视主板的画面处理芯片，把所有窗口叠好，控制每秒刷新多少帧
3. **Encoder**：把内部画面转成HDMI传输信号
4. **Connector**：HDMI插口本身
