Ray 容器是什么？

ray_container 是 Ray 集群的 "控制中枢"，它里面运行了：

┌─────────────┬───────────────────────────────────────────────────────────────────────────────────────────┐
│ 进程        │ 作用                                                                                      │
├─────────────┼───────────────────────────────────────────────────────────────────────────────────────────┤
│ gcs_server  │ Ray 的全局状态服务（Global Control Service），存储所有节点、actor、placement group 的信息 │
├─────────────┼───────────────────────────────────────────────────────────────────────────────────────────┤
│ dashboard   │ Ray Dashboard，Web UI + REST API（端口 8265），neutree-core 通过它查询集群状态            │
├─────────────┼───────────────────────────────────────────────────────────────────────────────────────────┤
│ raylet      │ 每个 Ray 节点上的守护进程，管理该节点的资源（CPU/GPU/内存）和任务调度                     │
├─────────────┼───────────────────────────────────────────────────────────────────────────────────────────┤
│ serve proxy │ Ray Serve 的请求代理（端口 8000），接收外部 HTTP 请求并路由到正确的 replica               │
├─────────────┼───────────────────────────────────────────────────────────────────────────────────────────┤
│ python app  │ 你的 Serve Application（包含 Controller + Backend deployment）                            │
└─────────────┴───────────────────────────────────────────────────────────────────────────────────────────┘

为什么要用两个容器？

这是 DOOD 架构（Docker-outside-of-Docker）的设计：

```
  Ray 容器 (ray_container)
  ├── 负责：Ray 集群管理、任务调度、请求路由
  ├── 特点：常驻运行，轻量级
  └── 挂载了 /var/run/docker.sock

      ↓ 通过 docker.sock 在宿主机上创建

  Engine 容器 (engine-llama-cpp)
  ├── 负责：实际加载模型、执行推理
  ├── 特点：每个 deployment 一个，重量级（包含模型文件）
  └── 用完即销毁（--rm）
```

为什么这样设计？

1. 引擎版本隔离：不同 endpoint 可以用不同版本的 llama-cpp（v0.3.7、v0.4.0 等），互不干扰
2. 资源隔离：Engine 容器可以独立限制 GPU/内存，不会影响 Ray 集群本身
3. 快速迭代：更新模型或引擎版本时，只需重启 Engine 容器，不用重启整个 Ray 集群

我们调试过程中看到的证据

```bash
  # Ray 容器内的进程（head 节点核心服务）
  docker exec ray_container ps aux | grep ray
  # → gcs_server、dashboard、monitor、serve proxy 都在这里

  # Engine 容器（实际推理）
  docker ps | grep engine
  # → neutree/engine-llama-cpp:v0.3.7-ray2.53.0

  # Ray 容器配置了 docker.sock，所以能在容器内"外发"创建 engine
  docker exec ray_container env | grep RAY
  # → RAY_EXPERIMENTAL_RUNTIME_ENV_CONTAINER_RUNTIME=docker
```

请求流转路径

```
  用户请求
      │
      ▼
  curl http://10.0.0.2:8000/default/qwen-coder-inference/v1/chat/completions
      │
      ▼
  ┌──────────────┐
  │  serve proxy │  ← 在 ray_container 内，负责路由
  │  (port 8000) │
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │  Controller  │  ← 在 ray_container 内的 engine 容器中
  │  (FastAPI)   │    或直接在 ray_container 内（取决于配置）
  └──────┬───────┘
         │
         ▼
  ┌──────────────┐
  │   Backend    │  ← 在独立的 engine 容器内
  │  (llama-cpp) │    加载 GGUF → 执行推理 → 返回 token
  └──────────────┘
```

简单总结：Ray 容器是"调度中心"，Engine 容器是"干活的工人"。 Ray 容器决定把请求发给哪个 Engine 容器，Engine 容器负责实际跑模型。
