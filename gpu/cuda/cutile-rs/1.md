# cutile-rs

项目地址：<https://github.com/nvlabs/cutile-rs>

本地源码：`/home/martins3/data/cutile-rs`

cuTile Rust 是一个 Rust/CUDA workspace，用于编写和 JIT 编译 tile-based GPU
kernel。它不是常驻服务；构建后通常通过 example、test 或 benchmark 验证。

## 环境要求

- Linux；上游主要在 Ubuntu 24.04 上测试。
- NVIDIA GPU，compute capability 至少为 `sm_80`。
- CUDA 13.3（推荐）。
- Rust 1.89 或更新版本。

## 方法一：使用 Nix 构建（本机推荐，已验证）

### 直接构建

仓库根目录的普通 `cargo build` 会构建 `default-members`，不会触发非常耗时的
`cuda-tile-rs`/LLVM 源码构建：

```bash
cd /home/martins3/data/cutile-rs || exit
nix develop -c cargo build
```

构建 release 版本：

```bash
cd /home/martins3/data/cutile-rs || exit
nix develop -c cargo build --release
```

构建所有常规 workspace crate，并显式排除重型的 `cuda-tile-rs`：

```bash
cd /home/martins3/data/cutile-rs || exit
nix develop -c cargo build --workspace --exclude cuda-tile-rs
```

只构建指定 crate：

```bash
cd /home/martins3/data/cutile-rs || exit
nix develop -c cargo build -p cutile
nix develop -c cargo build -p cutile-kernels
nix develop -c cargo build -p cutile-examples
```

### 进入交互式开发环境

需要连续执行多条命令时，可以只进入一次环境：

```bash
cd /home/martins3/data/cutile-rs || exit
nix develop
cargo build
cargo run -p cutile-examples --example hello_world
```

退出环境使用 `exit` 或按 `Ctrl-D`。

首次执行 `nix develop` 会下载并组装 CUDA 13.3、nightly Rust、clang、bindgen
等依赖，耗时和磁盘占用都明显高于后续执行。Nix store 与 Cargo `target/` 缓存
完成后，再次构建会快很多。

## 方法二：使用系统 CUDA 和 Rust 构建

系统环境需要自行安装 Rust 1.89+、CUDA 13.3、clang、CMake、Ninja、pkg-config
等依赖。建议显式指定 CUDA 路径：

```bash
cd /home/martins3/data/cutile-rs || exit
export CUDA_TOOLKIT_PATH=/usr/local/cuda-13.3

```

release 构建：

```bash
cd /home/martins3/data/cutile-rs || exit

```

`/usr/local/cuda-13.2`、`/usr/local/cuda-13` 和 `/usr/local/cuda` 等位置。

当前机器没有可直接调用的系统 `rustc`，且 CUDA 是 13.1，所以这里的原生方式

## 单独构建 cuda-tile-rs

`cuda-tile-rs` 被排除在 workspace 的 `default-members` 之外。第一次构建会通过
CMake 下载固定版本的 LLVM，并从源码编译 LLVM、MLIR 和 cuda-tile，可能需要
几十分钟到一小时、数 GB 磁盘空间和网络访问。

推荐启用持久缓存后显式构建：

```bash
cd /home/martins3/data/cutile-rs || exit
nix develop -c env CUDA_TILE_RS_CACHE=1 cargo build --release -p cuda-tile-rs
```

默认持久缓存位于 `$XDG_CACHE_HOME/cuda-tile-rs/`；未设置
`XDG_CACHE_HOME` 时位于 `$HOME/.cache/cuda-tile-rs/`。启用这个缓存后，
`cargo clean` 不会删除已经编译好的 LLVM 缓存。

如需同时安装 `cuda-tile-translate`，目标目录必须事先存在：

```bash
mkdir -p /home/martins3/.local/bin
cd /home/martins3/data/cutile-rs || exit
nix develop -c env CUDA_TILE_RS_CACHE=1 CUDA_TILE_TRANSLATE_INSTALL_DIR=/home/martins3/.local/bin cargo build --release -p cuda-tile-rs
```

## 常见问题

### 找不到 rustc

本机当前全局 PATH 中存在 Nix profile 提供的 `cargo`，但没有 `rustc`。直接使用
`nix develop -c ...`，或先进入 `nix develop` 后再执行 Cargo 命令。

### 找不到 CUDA、tileiras 或 libcuda

优先使用仓库 Nix flake。它会提供 CUDA toolkit，并在非 NixOS 系统上从常见
系统目录定位 NVIDIA driver library。原生构建则应检查：

```bash
echo "${CUDA_TOOLKIT_PATH:-not set}"
command -v tileiras
ldconfig -p | grep 'libcuda\.so'
```

## cutile-rs 的定位是什么?

`cutile-rs` 可以理解为 **cuTile 编程模型的 Rust 版实现/前端**，但它不是 `cutile-python` 的简单 Rust binding。

两者关系如下：

```text
cuTile Python 代码 ── Python 前端 ─┐
                                  ├─> CUDA Tile IR ─> tileiras ─> GPU cubin
cuTile Rust 代码 ── Rust 前端 ────┘
```

| 项目 | `cutile-python` | `cutile-rs` |
|---|---|---|
| 编程语言 | Python | Rust |
| Kernel 写法 | `@ct.kernel` | `#[cutile::module]`、`#[cutile::entry]` |
| 前端实现 | Python/C++ | Rust 过程宏和编译器 |
| 共同底层 | CUDA Tile IR | CUDA Tile IR |
| 主要特点 | 易用、接近 Triton 风格 | Rust 类型系统、所有权及并发安全 |
| 项目定位 | NVIDIA 官方 cuTile Python | NVLabs 研究性质的 cuTile Rust |

例如 Python 版：

```python
import cuda.tile as ct

@ct.kernel
def add(x, y, out):
    ...
```

Rust 版：

```rust
#[cutile::module]
mod kernel {
    #[cutile::entry()]
    fn add(
        z: &mut Tensor<f32, ...>,
        x: &Tensor<f32, ...>,
        y: &Tensor<f32, ...>,
    ) {
        ...
    }
}
```

`cutile-rs` 的核心增量是把 Rust 所有权延伸到 GPU kernel launch 边界：

- `&Tensor` 表示共享只读输入；
- `&mut Tensor` 表示独占可写输出；
- 输出 tensor 在 launch 前被划分成互不重叠的区域；
- 编译期尽量防止数据竞争；
- 支持异步执行和 CUDA Graph，同时保持所有权约束。

因此，最准确的理解是：

> `cutile-python` 和 `cutile-rs` 是同一个 CUDA Tile/Tile IR 技术体系下的两个独立语言前端，而不是彼此包装；`cutile-rs` 更强调利用 Rust 类型与所有权实现安全 GPU 编程。

目前 `cutile-rs` 官方仍将其描述为早期、研究性质且 API 可能变化的项目。
[cutile-rs 官方说明](https://github.com/NVlabs/cutile-rs)；
Python 版本则位于 [NVIDIA/cutile-python](https://github.com/NVIDIA/cutile-python)，
两者最终都生成 NVIDIA 的 [CUDA Tile IR](https://docs.nvidia.com/cuda/tile-ir/latest/index.html)。
